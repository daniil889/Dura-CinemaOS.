# Участие в разработке tvOS Launcher

Спасибо, что помогаете. tvOS Launcher — это домашний экран для Android TV в стиле tvOS 26: чистый
Java, без Gradle, без сторонних runtime-библиотек, рассчитанный на плавную работу на слабых
ТВ-приставках. Это руководство рассказывает, как с ним работать; чтобы сначала настроить машину,
см. **[docs/getting-started.md](docs/getting-started.md)**.

> Это русский форк проекта **[techgenius1/tvOS-Launcher](https://github.com/techgenius1/tvOS-Launcher)**.
> Правки, касающиеся перевода, присылайте в этот репозиторий; исправления самого лаунчера лучше
> предлагать в оригинальный проект.

## 1. Проект на одной странице

```
AndroidManifest.xml      пакет com.techgenius.tvoslauncher, активности/сервисы/приёмники
build.sh                 вся сборка (aapt2 → javac → d8 → zipalign → apksigner)
build.ps1                то же для Windows (PowerShell)
src/com/techgenius/tvoslauncher/   лаунчер (≈9 400 строк Java)
src/com/techgenius/tvoslauncher/present/   режим презентации: HTTP-сервер, плеер, хранилище
src/io/nayuki/qrcodegen/ вендоренный генератор QR (MIT)
res/                     ресурсы манифеста: иконки, XML администрирования устройства и спец.
                         возможностей, строки (values, values-ru и другие языки)
assets/fonts/            Inter (OFL)
assets/present/          админ-приложение презентации для браузера (HTML/CSS/JS)
docs/                    документация для пользователей и разработчиков, скриншоты
```

Ключевые файлы (полная карта — в **[docs/architecture.md](docs/architecture.md)**):

| Файл | Что там |
|---|---|
| `MainActivity.java` | Главный экран: док/сетка, фокус, карусель, строка состояния, панель управления, интерфейс профилей, Liquid Glass, режим бездействия |
| `SettingsActivity.java` | Страницы настроек |
| `SetupActivity.java` | Страницы первичной настройки |
| `Suggestions.java`, `News.java` | Содержимое карусели (рекомендации JustWatch/TMDB/Stremio, RSS новостей) |
| `Search.java`, `SearchPanel.java` | Поиск: названия на каждом сервисе с «Открыть» / «Получить», приложения и настройки; экран поиска |
| `MediaWatchService.java` | «Продолжить просмотр» из медиасессий |
| `Weather*.java` | Данные о погоде, плитка и панель прогноза, иконки |
| `Perms.java`, `PowerService.java` | Экранные потоки разрешений; служба спец. возможностей для выключения / очистки |
| `AirPlayGuard.java`, `Inputs.java`, `Clicks.java`, `Profiles.java` | Наблюдатель AirPlay, ТВ-входы, звуки, профили |
| `Ui.java`, `Glyphs.java` | Размеры (расчётная сетка 960×540), шрифты, глифы, нарисованные в коде |
| `I18n.java`, `I18nHe.java`, `I18nHeData.java` | Языки, словари, шаблоны строк со значениями, RTL |

Возможности описаны в **[docs/features.md](docs/features.md)**.

## 2. Процесс работы

- `main` защищён: **никогда не пушьте в него**. Работайте в ветке и открывайте pull request;
  для слияния нужно одобрение.
- Имена веток: `feature/<короткое-имя>`, `fix/<короткое-имя>`, `docs/<короткое-имя>`,
  `i18n/<короткое-имя>`.
- Держите pull request сфокусированным на одной вещи; несколько маленьких лучше одного огромного.
- Сообщения коммитов: короткая строка-сводка в повелительном наклонении (≤ 72 символа), пустая
  строка, затем *что* и *зачем* несколькими пунктами. Укажите, что вы тестировали и на каком
  устройстве.

```
Погода: пробовать следующий источник при таймауте

- Из-за таймаутов Open-Meteo плитка оставалась пустой до следующего тика в 15 минут.
- Проверено на Mi Box (Android 12): отключил сеть на 30 с, плитка восстановилась.
```

- Меняйте версию только в релизных сборках (`VERSION_CODE`/`VERSION_NAME` в командной строке
  `build.sh`), а не в исходниках.

## 3. Стиль кода

Подстраивайтесь под окружающий код; согласованность важнее любых правил ниже.

- **Уровень языка Java 11**, Android API 23+ (`minSdk 23`, `targetSdk 34`). Более новые API
  закрывайте проверками `Build.VERSION.SDK_INT`.
- **Никаких новых runtime-библиотек.** APK весит ~6 МБ и не имеет зависимостей; так и оставьте.
  Небольшой код с разрешительной лицензией можно вендорить в `src/` вместе с его лицензией (как
  QR Nayuki).
- **Представления в коде**, без XML-раскладок. Следуйте существующим шаблонам (`row(...)`,
  `ccTile(...)`, `option(...)`, `LiquidGlass`).
- **Размеры в расчётных единицах**: всегда `dp(x)` / `Ui.px(ctx, x)`, никогда не сырые пиксели,
  чтобы 720p, 1080p и 4K сохраняли пропорции. Текст — через `Ui.textSize`.
- **Шрифты**: `Ui.font(ctx, "regular" | "medium" | "semibold" | "display")` (Inter).
- **Только ASCII в исходниках.** Не-ASCII символы пишите как escape-последовательности `\uXXXX`
  (например, `"\u00b0"` для °). Это же правило действует для новых русских строк в `I18n.java`:
  словарь `initRussian()` хранит кириллицу в `\uXXXX`-виде, как и остальные языки.
- **Комментарии**: короткий Javadoc у каждого класса и у неочевидных методов, объясняющий *почему*,
  в плотности окружающего кода. Никакого закомментированного кода.
- **Потоки**: сеть, диск и декодирование битмапов — вне UI-потока (executor `io` или `Thread`);
  результаты возвращайте через `handler`.
- **Строки**: пользовательский текст — со строчной буквы для строк списков, с заглавной для
  кнопок и заголовков, как у Apple; коротко и просто. Все новые строки должны быть добавлены в
  `I18n.java` (минимум в английский и русский словари), иначе русская сборка покажет английский
  текст.

## 4. Правила дизайна

Смысл tvOS Launcher — выглядеть и ощущаться как Apple tvOS 26. Перед созданием UI:

- **Сначала измерьте реальный интерфейс Apple** (скриншоты tvOS и Human Interface Guidelines),
  затем реализуйте и укажите измеренные числа в коде или PR. Не импровизируйте с внешним видом.
- Liquid Glass — для **элементов управления и панелей** (док, кнопки, панель управления, плитки).
  Карточки приложений остаются непрозрачными.
- Фокус: подъём/масштаб (карточки 1,2×, элементы управления ~1,06–1,12×), белое состояние фокуса
  для кнопок и плиток, никогда цветной контур. Убедитесь, что у элементов в фокусе есть место для
  роста (без обрезки родителями).
- Текст должен оставаться читаемым поверх любых изображений: используйте существующие затемнения,
  минимальный размер текста 11,5 расчётных единиц (≈ минимум 23 pt у Apple в tvOS).
- Всё должно работать с 5-кнопочным пультом (стрелки, OK, «Назад», «Домой»): каждый элемент в
  фокусе достижим, фокус никогда не теряется, «Домой» всегда возвращает к первому приложению
  в доке.

## 5. Правила производительности

Цель — Mi Box 4 (GPU Mali-450 MP, GLES 2.0, ограничен скоростью заливки). Навигация по главному
экрану должна держаться около 16 мс медианного времени кадра.

- **Никаких постоянных анимаций.** Главный экран в простое рисует ~0 кадров в секунду.
- **Ничего не рисуется программно в UI-потоке во время переходов.** Дорогое (размытие, градиенты,
  стеклянные фоны) запекайте в битмапы один раз.
- Избегайте скрытых полноэкранных слоёв и перерисовки; лучше одно запечённое изображение, чем
  несколько наложенных.
- Кэшируйте результаты сети и изображения на диске; никогда не блокируйте запуск сетью.

Измеряйте до и после любого визуального изменения:

```sh
adb shell dumpsys gfxinfo com.techgenius.tvoslauncher reset
# …несколько раз нажмите вправо/влево по доку…
adb shell dumpsys gfxinfo com.techgenius.tvoslauncher | grep -E "Janky|50th|90th"
```

Укажите числа в PR. `--es perf <слой>` (см. getting-started) помогает найти дорогие слои.

## 6. Правила разрешений и приватности

- **adb — крайняя мера.** У каждого разрешения должен быть экранный путь, где телевизор это
  позволяет (системный запрос, собственный экран настроек, переключатель спец. возможностей,
  запрос роли), и корректная деградация с понятным сообщением там, где телевизор этого не умеет.
  Новые потоки добавляйте в `Perms.java`.
- Определяйте, что поддерживает устройство, прежде чем предлагать возможность (например,
  телевизоры с малым объёмом ОЗУ не могут выдать доступ к уведомлениям; у некоторых телевизоров нет
  функции администрирования устройства).
- Служба спец. возможностей (`PowerService`) делает только то, что пользователь попросил из tvOS
  Launcher (сон, закрытие приложений). Не расширяйте её до чтения содержимого экрана.
- Никакой аналитики, отслеживания, аккаунтов. Сетевые вызовы идут только к источникам контента,
  нужным функции (погода, новости, рекомендации, поиск, определение по IP), и никогда не передают
  персональные данные. Поисковые запросы уходят только в JustWatch (и в каталог Cinemeta Stremio,
  если установлены Stremio/Nuvio); недавние запросы остаются на телевизоре.
- Микрофон используется только пока пользователь диктует в поиске (после системного запроса
  Android); tvOS Launcher сам никогда не записывает и не хранит звук.
- Никогда не коммитьте секреты (API-токены, пароли) — ключи TMDB вводит пользователь во время
  работы.

## 7. Проверка изменения

Автоматического набора тестов пока нет; изменения проверяются на устройствах. Для каждого
изменения:

1. `./build.sh` (или `.\build.ps1`) завершается без новых предупреждений, которые вы внесли.
2. Установите и проверьте изменение пультом (или `adb shell input keyevent …`), включая «Назад» и
   «Домой» с каждого нового экрана.
3. Сделайте скриншоты новых или изменённых экранов (`adb exec-out screencap -p > shot.png`) и
   приложите их к PR.
4. Если изменение касается главного экрана, запишите время кадров (см. §5).
5. Если оно касается разрешений, сети или хранилища, проверьте и на устройстве с Android 12, и на
   **Android 9 / 1 ГБ ОЗУ**, а также с выключенной сетью.
6. Проверьте `adb logcat -s TvHome AndroidRuntime` на ошибки и падения.
7. Для изменений перевода пройдите по затронутым экранам с русским языком и убедитесь, что нигде не осталось английского текста (см. [docs/translation.md](docs/translation.md)).

Чек-лист для изменений UI: читаемо поверх светлых и тёмных изображений · ничего не обрезается в
фокусе · достижимо стрелками · «Домой» возвращает в док · 720p и 1080p выглядят правильно.

## 8. Pull request'ы

Открывайте PR в ветку `main` с:

- **Что и почему** (ссылка на issue, если он есть).
- **Скриншотами** каждого изменённого экрана.
- **Как вы тестировали**: устройства, версия Android, шаги.
- **Числами времени кадров** для изменений главного экрана.
- Обновлённой документацией, если поведение изменилось (`docs/features.md`, а для новых файлов —
  `docs/architecture.md`).

Проверяющие смотрят: соответствует дизайну tvOS, нет регрессии производительности, работает с
пультом, разрешения следуют §6, код следует §3.

## 9. Хорошие первые задачи

- Новые иконки погоды (`WeatherIcons.java`) или иконки разъёмов (`Glyphs.java`).
- Дополнительные ленты городских новостей (`News.java`, `TOI_CITIES` и слаги городов).
- Дополнительные стриминговые сервисы для рекомендаций (`Suggestions.java`, `PROVIDERS`).
- Улучшение переводов: вычитка русских строк, добавление склонений и форматов дат в
  `I18n.java` (см. [docs/translation.md](docs/translation.md)).
- Автоматические проверки: скрипт сборки и линтинга или JVM-тесты для парсеров (погода, новости,
  модель плейлиста).
- Доступность: метки TalkBack для собственных представлений.

### Подпись

Отладочные сборки подписываются локальным `debug.keystore`, который `build.sh` создаёт при первом
использовании; он игнорируется git. **Релизные сборки подписывают только сопровождающие**, приватный
ключ хранится в отдельном приватном репозитории (никогда в этом):

```sh
RELEASE_KEYSTORE=/path/to/tvos-release.jks RELEASE_KEYSTORE_PASS=... VERSION_CODE=.. VERSION_NAME=.. ./build.sh
```

Отладочная сборка не может обновить релизную установку (другой ключ): сначала удалите приложение.
